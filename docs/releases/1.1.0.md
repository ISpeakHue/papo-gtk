# Papo 1.1.0

Linux is stable. The Windows downloads are **experimental and unsigned**.
macOS remains groundwork and has no application bundle.

## Changes

- Merge the Windows-first multiplatform work into the shared frontend while retaining Linux packaging and future macOS platform boundaries.
- Add a self-contained Windows portable ZIP and per-user installer with native credential storage, notifications, media isolation and consent-based screen capture.
- Improve Windows call devices and sounds, screen-capture resizing, text rendering, keyboard/IME handling and scrolling.
- Include the Windows GTK IME disposal backport and GStreamer Unicode executable-path correction.
- Keep application control icons consistent across desktop themes, and run Windows/macOS checks against `main`.
- Preserve complete installer probe diagnostics and isolate developer-toolchain test fixtures from host paths.

## Downloads

- **Linux x86_64:** AppImage for current distributions and a Flatpak bundle using the GNOME 50 runtime. See [AppImage instructions](../../APPIMAGE.md) and [Flatpak instructions](../../FLATPAK.md).
- **Windows x86_64 — experimental:** per-user `.exe` installer or portable ZIP. Extract the complete ZIP and open `Papo.exe`. Rust, MSYS2, Python and GStreamer do not need separate installation. Uninstall preserves settings, caches and saved sessions.
- SHA-256 checksums, matching frontend source and source/recipes for modified native libraries accompany the packages.

## Known limitations

Windows is unsigned because no signing certificate is available. An unknown-publisher or reputation prompt is expected. Automated Windows Server checks and existing user testing do not complete the Windows 11 Home/Pro, device, accessibility and beta acceptance matrix. See the [Windows policy](../../WINDOWS_SUPPORT.md).

The Linux playback-teardown crash was diagnosed by the owner as an external GStreamer issue. Its regression result remains visible; the frontend does not claim to fix that dependency crash. The release verification report records actual CI outcomes, including this known failure, separately from passing package checks.

macOS compile/link checks support future work and do not establish a working macOS release. Byte-identical rebuilding has not been demonstrated.
