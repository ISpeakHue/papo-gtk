## Notifications

Opening the inbox acknowledges accessible unread notifications automatically.
Persisted notices use bulk requests of at most 1,000 IDs, with in-flight
request deduplication. New pages are acknowledged while the inbox is open.
Failed writes stay retryable and their error survives overlapping refreshes;
refreshing does not create an automatic failure/retry loop. Live events are
marked seen locally and acknowledged on the server when their persisted
records arrive, including after the inbox closes. Unknown or inaccessible
channel contents remain protected.

The mapped regression checks failed writes, successful retry, automatic reads
on pagination, one write for five notices, and delayed persistence of a seen
live event. Direct-message response delivery also tolerates component shutdown
without panicking in a background task.

## Recent channels

The existing session cache retains message metadata for eight recent channels.
A second cache now retains text rows and measured heights for two recent
channels, avoiding reconstruction of hundreds of GTK widgets on a warm visit.
Each entry is bounded to 210 rows and 2 MiB of row signatures; the aggregate
signature budget is 4 MiB. These budgets account for signatures rather than
claiming to measure GTK's native heap usage. Large media widgets, players,
animation pictures, and avatar textures are released before rows are cached.
Small inline emoji paintables remain in their text buffers. Restored avatars,
permissions, message edits/deletions, grouping, and action sensitivity are
revalidated. Session changes and permission invalidation clear both caches.

Returning to the newest messages now drops older loaded pages beyond the last
200 messages. They remain available through normal pagination. The inactive row
cache also excludes those older pages. Decoded images, GIF frames and cached video
files are released on channel switches; only bounded dimensions and embed metadata
remain. After scrolling settles, media beyond the nearby viewport is replaced by
placeholders with the same geometry, releasing its GTK paintables as well as cache
entries. Open image viewers and fullscreen playback retain their displayed media.
Late image completions cannot refill an evicted asset.

The mapped 1,000-message fixture reuses 199 of the 200 message rows on a warm
visit and checks inactive edits and deletions. Scroll restoration retains its
anchor through the first two visible frames to handle late allocations; this
does not extend the opening cover by a fixed loading delay.

## Unread boundary

A themed line labelled “Mensagens não lidas” appears immediately before the
first unread message. It remains stable during live updates and is recreated
for each channel visit. Author grouping starts afresh at this boundary. The
regression checks placement, visibility at the opening anchor, and row reuse.

## Profile editor

The editor uses a native libadwaita window/header, an always-visible Save action,
a width clamp, grouped EntryRows, image actions, and a multiline description.
Availability and typing status have their own group. Existing validation,
server-confirmed writes, failed-save draft retention, and image-update draft
restoration remain supported. Normal and narrow layouts are checked, with
optional screenshots generated by the test harness.

Design reference: [GNOME secondary-window guidance](https://developer.gnome.org/hig/patterns/containers/windows.html).

## GIF providers

Tenor and Klipy links share the bounded animation pipeline with Giphy. A
separate public client never forwards the Papo session; it accepts exact
provider/CDN hosts, limits download sizes, rejects redirects and alternative
ports/credentials, and does not execute page scripts. GIFs in code blocks are
excluded. Provider embed metadata supplies trusted GIF URL hints when present.
Tenor's supplied page exposes a 13 MB original GIF and a 1.2 MB `tinygif`; the
resolver selects the smaller rendition published for that exact post.

Animated embed thumbnails suppress duplicate raw-link previews and their Play
button. If public GIF retrieval fails and the backend supplies video metadata,
the authorized video endpoint provides an at-most-8-MiB local file. An isolated
GStreamer worker decodes it into silent animation frames (up to 60 seconds,
10 fps and 48 MiB of frame pixels), using the existing GIF paintable to loop.
The worker is cancelled and killed when its task is cancelled; shared temporary
files remain owned until decoding finishes. Automatic GIF fallback creates no
GTK player and cannot evict a user-started video. Cleanup on channel exit is
checked. Cached static thumbnails upgrade to full animations once; pending
and resolved GIF requests are deduplicated. Other embedded videos retain their existing audio behavior.

The supplied Tenor GIF was downloaded and decoded successfully. The supplied
Klipy page returned HTTP 403 in this environment, so its live media could not
be verified here. Klipy playback requires accessible provider GIF data or
usable GIF/video metadata from the backend; provider denial is not bypassed.

## Up to edit

Unmodified Up in an empty composer opens the existing editor for the newest
message authored by the current user in the current channel. Draft text,
attachments, replies, embeds, and completion navigation are protected. If the
message is outside the loaded cache, an owner/channel-filtered search locates
it and a bounded history lookup retrieves its complete metadata, preserving
custom embeds. Duplicate lookups are suppressed; changing channels or typing
while a result is pending prevents the editor from opening late.
