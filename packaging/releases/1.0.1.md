Papo 1.0.1 improves compatibility with the updated backend and video previews.

### Changes

- Reserve the original video aspect ratio before a poster loads, using the backend’s new video dimensions. Portrait videos keep the correct shape; missing or invalid dimensions fall back safely.
- Recognize older MOV/MP4/M4V/WebM attachments still recorded with generic MIME types.
- Keep AVI and Matroska attachments available as downloads without showing unsupported playback controls or requesting unusable previews.
- Preserve compatibility with older backend responses and existing media validation.

### Downloads

Both packages are **Linux x86_64** builds of this release:

- **AppImage:** `Papo-1.0.1-x86_64.AppImage`. Make it executable and launch it. Built with Fedora 44; requires **glibc 2.43 or newer**. Native desktop font settings and scaling are preserved. See the attached AppImage README.
- **Flatpak:** `Papo-1.0.1-x86_64.flatpak`. Install with `flatpak install --user ./Papo-1.0.1-x86_64.flatpak`, then run `flatpak run br.com.papo.gtk`. Uses the GNOME 50 runtime, downloaded from Flathub when needed. This is a standalone GitHub bundle, not a Flathub app listing or an automatic app update repository.

`SHA256SUMS` verifies the downloads. `papo-gtk-1.0.1-source.tar.gz` contains the matching frontend source and build recipes.

### Package checks

Validation passed: 282 automated Rust tests, six Python checks and three focused
GTK cases. Both packages report 1.0.1 and passed runtime, isolated media decoding
and private Wayland startup checks. The AppImage also passed font diagnostics.

The offline checks use synthetic media and no account or physical devices:

```sh
./Papo-1.0.1-x86_64.AppImage --runtime-check
./Papo-1.0.1-x86_64.AppImage --check-media-runtime
flatpak run --command=papo-runtime-check br.com.papo.gtk
```

Voice, camera and screen sharing require working desktop audio services and portals. Actual devices and GPU-specific hardware decoding need testing on the target desktop.
