# Papo 1.1.2

Linux AppImage and Flatpak update, including the recent chat improvements and repaired local audio-device tests.

## Audio-device tests

- Keep progress, completion and failure messages visible above the scrolling settings controls.
- Use Papo's own audio-server identity for local tests, preserving the application's mixer settings instead of inheriting Python's routing or mute profile.
- Prefer the actual PulseAudio/PipeWire audio-server devices for Linux tests so an unavailable output reports an error instead of silently falling back to fake playback.
- Play a two-second tone at a fixed source sample rate. Report a silent microphone recording explicitly, and explain when an ongoing device switch prevents testing.
- Exercise actual pointer clicks and the production worker. The virtual-device regression checks captured 3.1 seconds of 880 Hz microphone replay and 2.3 seconds of the 660 Hz output tone. No physical microphone recording was used for this check.

## Chat and workspace

- Switch between independent server accounts, preserving their drafts, conversations and unread state.
- Recover drafts and pending sends; keep composition independent of network completion.
- Drop local files into chat to stage attachments.
- Show optimistic messages immediately, with delayed sending controls for slower requests.
- Acknowledge visible messages promptly and prevent stale snapshots from restoring unread badges.
- Preserve the visible message while older history and media finish allocating during scrolling.
- Keep unchanged custom-emoji channel descriptions mapped during unread navigation and emoji refreshes.
- Add conversation switching, account-local media browsing, local cache controls and accessibility improvements.
- Use a narrower server rail with icon-only account buttons and hover details.

## Verification limits

Automated audio verification used generated signals and temporary virtual devices, with actual button activation and PCM analysis. Physical-device quality and compatibility are not inferred from those checks. The previously documented intermittent native GStreamer playback-teardown crash is not claimed fixed by this release.
