## Changes

- Share the Rust/GTK frontend across Linux and Windows, with macOS platform
  boundaries and compile/link checks prepared for a future port.
- Bundle the Windows GTK/libadwaita, Python/GI and native media runtime; launch
  without MSYS2, external Python or a terminal.
- Add per-user installation, versioned upgrades, recovery and ownership-checked
  uninstall that preserves settings and remembered sessions.
- Integrate native Windows credentials, notification activation, isolated media
  helpers and desktop input policies. Native WGC capture remains opt-in until
  its attended acceptance is complete.
- Bind source/toolchain/native inputs, installer/ZIP identity, signing and final
  acceptance reports to the exact distributed files.

## Windows downloads

The qualified release must provide:

- `Papo-1.1.0-windows-x86_64.exe`: per-user installer.
- `Papo-1.1.0-windows-x86_64.zip`: standalone application-owned runtime.
- `papo-gtk-1.1.0-source.tar.gz`: exact tested source and build recipes.
- `Papo-1.1.0-windows-notices.tar.gz`: dependency notices and license texts.
- `SHA256SUMS` and `Windows-qualification.json`: file identities and qualification.

Authenticode validates publisher identity and file integrity. It does not promise
SmartScreen reputation or eliminate security prompts. Keys stay with the owner;
Papo does not distribute signing certificates/private keys as runtime dependencies.
Byte-identical rebuilding has not been demonstrated.

Linux remains supported. The published Linux AppImage/Flatpak release is 1.0.2;
do not relabel those existing binaries as 1.1.0. macOS is groundwork, with no
supported `.app` or macOS download in this Windows release milestone.
